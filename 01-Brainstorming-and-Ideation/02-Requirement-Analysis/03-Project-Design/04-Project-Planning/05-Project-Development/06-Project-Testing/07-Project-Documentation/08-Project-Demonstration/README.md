# Phase 8 – Project Demonstration

## Project Title

**Implement Client Script & UI Policy (Incident)**

## 1. Demonstration Overview

The Project Demonstration phase presents the completed ServiceNow project and demonstrates the implemented Client Script and UI Policy functionality.

The demonstration will show the project purpose, configuration, execution process, testing, and final output.

## 2. Project Name

**Implement Client Script & UI Policy (Incident)**

## 3. Project Purpose

The purpose of the project is to implement Client Script and UI Policy functionality in the ServiceNow Incident application.

The project demonstrates dynamic form behaviour and ensures that the Assignment group field becomes mandatory when the Incident Impact is set to 1 - High.

## 4. Project Benefits

The project demonstrates the following benefits:

- Improves Incident form behaviour.
- Helps ensure required information is entered.
- Provides dynamic field control.
- Improves consistency in Incident records.
- Demonstrates practical ServiceNow administration skills.

## 5. Demonstration Flow

The project demonstration will follow this sequence:

1. Introduce the project name.
2. Explain the purpose of the project.
3. Explain the problem being addressed.
4. Open the ServiceNow Developer Instance.
5. Open the Incident application.
6. Show the Incident form.
7. Demonstrate the Client Script configuration.
8. Demonstrate the UI Policy configuration.
9. Show the UI Policy name: **High Impact Control**.
10. Show the condition: **Impact is 1 - High**.
11. Show the Assignment group UI Policy Action.
12. Demonstrate that Assignment group becomes mandatory when Impact is 1 - High.
13. Change the Impact value and demonstrate the Reverse if false behaviour.
14. Show the final working output.
15. Summarize the project.

## 6. Final Output

The final output demonstrates that:

**Impact = 1 - High**

causes:

**Assignment group → Mandatory**

When the condition becomes false, the configured Reverse if false behaviour is applied.
